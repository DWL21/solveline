# 로드맵

지금 하지 않는 일과 그 일을 위해 미리 지킬 원칙을 적는다. 순서는 우선순위가 아니다.

## 계정별 확장 (예정)

- 지금은 단일 사용자(비밀번호 1개)다. 여러 계정으로 넓힐 때 문제·폴더·컬렉션·제출에 소유자를 붙인다.
- 코드 실행은 사용자 수에 비례해 늘어나므로 api와 실행기를 분리해 따로 늘릴 수 있게 둔다 (실행 파이프라인 개선 참고).

## 기존 문제 전체 이식 (예정, 착수 전)

- 기존(기존) 문제를 모두 옮겨 올 계획이다. **아직 시작하지 않는다.**
- 대비할 점
  - 수만 개 문제와 큰 테스트 데이터: 테스트 데이터를 문제 본문(JSON)이 아니라 파일/객체 저장소에 두고 실행기가 캐시해서 읽는 구조가 필요하다.
  - 표준 입출력형이 대부분이고 스페셜 저지(정답이 여러 개)가 있다: 채점기를 문제별로 끼울 수 있어야 한다.
  - 언어별 시간 제한 배수(예: Java·Python 추가 시간)와 메모리 제한.
  - 문제 지문의 저작권·라이선스는 문제마다 다르므로 이식 전에 확인한다.

## 실행 파이프라인 개선 (진행 예정)

- 기존·기존의 채점 구조를 검토하고, 대량 처리에 맞게 가볍게 다시 설계한다. 결정은 `docs/decisions/`에 남긴다.
