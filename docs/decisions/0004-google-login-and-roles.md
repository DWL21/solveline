# 0004. Google 로그인, 공용 문제집과 편집 권한

- 상태: 채택 (2026-10-23)
- 대체: [0002](0002-password-login.md)의 비밀번호 로그인 (비밀번호는 관리자 모드의 마스터 비밀번호로 남는다)

## 배경

단일 사용자용에서 여러 사람이 쓰는 서비스로 넓힌다. 문제는 모두가 같이 풀고, 풀이 기록은 사람마다 따로 남아야 한다(기존와 같은 구조).

## 결정

- **로그인**: Google OAuth(Authorization Code + PKCE). 로그인과 회원가입 모두 Google이고, 처음인 계정만 약관 동의 화면을 거친다. OAuth 왕복과 가입 대기 상태는 서명 쿠키(10분)에 둔다. 가입은 기본 허용이며, 마스터가 신규 가입을 전체 중지할 수 있다. 기존 회원 로그인은 유지한다.
- **공용**: 문제(제목·설명·보이는/히든 채점 케이스·시간 제한·시작 코드)와 폴더. 편집 권한(`role = editor`)이 있는 사용자만 편집 모드에서 바꾼다.
- **사용자별**: 작성 코드·언어·내 테스트 케이스·메모·풀이 시간·마지막 제출(`user_problems`), 컬렉션, 제출 기록.
- **비회원**: 문제·폴더 조회만(작성 코드 자리에는 시작 코드).
- **관리자 모드**: Google 계정과 별개로 마스터 비밀번호(`ACCESS_PASSWORD`)로만 연다. 편집 권한 부여·회수, 신규 가입 허용·중지, 사용자 현황 조회.
- **이전**: 비밀번호 시절의 작성 코드·풀이 시간·채점 결과는 `legacy_state`로 옮겨 두고, 운영자(`OWNER_EMAIL`)가 처음 가입할 때 넘겨받는다. 공용 시작 코드는 기본 틀로 되돌린 뒤 문제별 시그니처를 `PUT /api/admin/problems/{id}/starter`로 다시 넣는다.

## 결과

- 자동 저장(`PUT /api/problems/{id}`) 하나로 내 코드와(편집 권한이 있으면) 문제 내용을 함께 저장한다. 권한 없는 사용자가 보낸 문제 내용 변경은 무시한다.
- 누구나 가입할 수 있으므로 runner 샌드박스의 격리 수준이 곧 서비스의 보안 경계다. 남용은 사용자별 실행 횟수 제한(분당 30회)과 신규 가입 중지로 대응한다.

## 신규 가입 제어 (#49)

이메일 블랙리스트 및 사용자별 정지 API·UI를 제거한다. `signup_settings`에 가입 허용 여부를 저장하고, Google 콜백에서 기존 회원 여부를 먼저 확인한다. 신규 계정 생성 직전에도 설정을 다시 확인하여 이미 동의 화면에 들어온 계정의 가입도 차단한다. 기본값은 기존처럼 허용이며 운영자가 마스터 페이지에서 변경한다. 이전 블랙리스트 테이블은 마이그레이션에서 제거하며 기존 계정·풀이 기록은 유지한다.
