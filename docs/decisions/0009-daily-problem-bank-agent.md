# 0009. 일일 미니 문제 은행과 에이전트 자동 제작

## 배경

0008의 일일 메일은 관리자가 날짜별 회차를 하나 써서 모두에게 같은 문제를 보냈다. 문제를 계속 사람이 써야 하고, 실력과 무관하게 같은 문제를 받는다.

## 결정

1. **메일·인박스 전용 미니 문제.** 일반 문제와 같은 `problems` 행(예제·히든 테스트셋·시작 코드)이라 같은 IDE와 채점으로 푼다. `daily_bank`가 유형(topic)·난이도(level 1~5)·힌트·상태(draft/ready/retired)·만든 곳(source)을 둔다. 은행에 있는 문제는 일반 목록과 R2 카탈로그에서 빼고, 받은 사람이 링크(`/api/public/daily/problems/:id`, 추측할 수 없는 UUID)로 연다.
2. **검증을 통과해야 저장.** 문제를 만들 때 기준 풀이(referenceSolution)로 예제와 채점 케이스를 모두 실제 judge에서 채점해 100점일 때만 저장한다. 실패하면 틀린 케이스(기대값·실제값·오류)를 돌려줘 만든 쪽이 고친다. 관리자 화면과 에이전트가 같은 길(`saveDaily`)을 쓴다.
3. **사람마다 다른 문제.** `daily_picks`(사람·날짜 → 문제)에 그날 문제를 정해 두므로 메일과 인박스가 같은 문제를 보이고 다시 받지 않는다. 고르는 규칙(`pickProblem`): 정답률이 낮은 유형을 더 자주, 최근 받은 유형은 덜, 유형별로 잘 맞히면(≥70%) 한 단계 위·자주 틀리면(<40%) 한 단계 아래. 정답은 그 문제의 제출 중 100점이 있는지로 본다.
4. **처음 구독한 날은 바로 받는다.** 받은 문제가 없는 사람이 구독하면 그날 문제를 정하고 메일을 켰으면 바로 보낸다. 발송 기록을 먼저 남겨 07시 발송과 겹치지 않는다.
5. **무료 한도.** mailer는 한 번에 10명만 새로 고르고(한 사람 쿼리 3개, D1 호출당 50쿼리) 30통씩 보낸다. 07:00~07:55에 5분마다 12번 돌아 상한 90명을 덮는다.
6. **에이전트는 MCP로, 외부에 열지 않는다.** pahidc의 judge 컨테이너 안에서 stdio MCP 서버(`apps/judge/src/bank-mcp.ts`)를 실행한다. 도구 목록·입력 형식은 `@solveline/shared`의 `DailyBankTools`(Zod → JSON Schema)이고, 호출은 컨테이너의 `JUDGE_SECRET`으로 서명해 Worker의 `/api/internal/daily/bank`로 넘긴다. 접속은 SSH뿐이다: `ssh pahidc solveline-bank-mcp --agent <이름>`. 토큰 발급 절차가 없고 포트를 열지 않는다.
7. **모델 교체가 쉬운 자동 제작.** systemd 타이머(`solveline-bank-generate.timer`, 매일 04:00 KST)가 `solveline-bank-generate`를 실행하고, 이 스크립트가 에이전트 CLI(기본 Codex CLI, `BANK_AGENT_CLI=claude`도 지원)에 같은 MCP를 붙여 부족한 유형·난이도부터 새 문제를 만든다. 작성 지침(`DAILY_AUTHOR_GUIDE`)은 `bank_guide` 도구로 주므로 지침을 고치면 모든 모델에 함께 적용된다. 다른 모델은 MCP 클라이언트 설정만 더하면 된다.
8. **바로 공개.** 에이전트가 ready로 만든 문제는 바로 발송 대상이다(검증 통과가 전제). 관리자는 문제 목록에서 상태를 바꾸거나(retired) 받은 사람이 없는 문제를 지운다.

## 결과

- 날짜별 회차 표(`daily_issues`, `daily_inbox_reads`)를 없애고 발송 기록을 `pick_date` 기준으로 바꿨다(0003, 운영에 회차·발송 기록이 없을 때 적용).
- 관리자 화면: 유형×난이도 칸별 문제 수, 문제 직접 추가(에이전트와 같은 JSON), 상태 변경·시험 발송·삭제.
- 에이전트 CLI는 pahidc에 미리 로그인해 둔다(`~/.codex/auth.json`). 로그인이 풀리면 자동 제작만 멈추고 발송은 계속된다.
