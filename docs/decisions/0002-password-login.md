# 0002. 개인키 로그인을 비밀번호 로그인으로 대체

- 날짜: 2026-10-22
- 상태: 채택 (0001의 접근 결정 1번을 대체)

## 배경

Ed25519 개인키 파일은 기기를 바꿀 때마다 옮겨야 하고, 휴대폰·공용 PC에서 쓰기 어렵다. 사용자는 나 혼자이고, 비밀 값은 이미 GitHub Environment로 관리하고 있다.

## 결정

- 24자 이상 랜덤 비밀번호 하나(`ACCESS_PASSWORD`)로 로그인한다. 원본은 GitHub Environment `production` secret에만 두고, 배포 시 서버 `/etc/codetest/api.env`(root 600)에 기록한다.
- 서버는 SHA-256 해시끼리 `timingSafeEqual`로 비교한다(길이·내용이 시간으로 새지 않게).
- 대입 공격 방지: IP별 분당 5회, 전체 시간당 60회. 24자 base64url(약 144비트)이라 이 속도로는 추측할 수 없다.
- 운영에서 비밀번호가 없거나 짧으면 api가 시작하지 않는다.
- 세션 쿠키(HttpOnly·Secure·SameSite=Strict, 서버 저장, 30일)는 그대로 쓴다.

## 결과

- 브라우저 비밀번호 관리자로 어느 기기에서든 로그인할 수 있다.
- 비밀번호가 새면 GitHub secret을 바꾸고 배포를 다시 돌리면 된다. 기존 세션은 `SESSION_SECRET`을 함께 바꾸면 모두 끊긴다.
- 개인키 방식보다 피싱·유출에 약하다. 단일 사용자 + 시도 제한 + 긴 랜덤 값으로 감수한다.
