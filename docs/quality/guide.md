# 팀 적용 가이드

## 처음 오는 사람의 30분

1. `pnpm install && pnpm --filter @solveline/e2e exec playwright install chromium webkit`
2. `scripts/test-env.sh up` — 운영과 같은 이미지로 테스트 환경을 띄운다
3. `pnpm --filter @solveline/e2e e2e:ci` — 전체 자동화를 돌려 본다
4. `pnpm --filter @solveline/e2e report` — 리포트에서 trace를 열어 테스트가 무엇을 하는지 본다
5. `e2e/tests/api/permissions.spec.ts`의 표에 한 줄을 더해 보고, 일부러 틀린 기댓값을 넣어 실패 메시지를 확인한다

## 어디에 테스트를 쓰나

| 확인하려는 것 | 층 | 위치 |
|---|---|---|
| 함수·저장소·규칙의 경우의 수 | 단위 | `apps/api/test` |
| HTTP 계약·권한·채점 결과 | API | `e2e/tests/api` |
| 사용자가 화면에서 하는 일 | UI | `e2e/tests/ui` (핵심 여정만) |
| 배포된 사이트가 살아 있는지 | 스모크 | `e2e/tests/smoke` (읽기 전용) |

같은 규칙을 여러 층에서 반복하지 않는다. 화면 테스트로 규칙의 모든 경우를 확인하려 하지 말고, 경우의 수는 아래층에서 표로 덮는다.

## 작성 규칙

- **이름이 명세다**: "무엇을 하면 → 어떻게 된다". 예) `제출하면 히든 케이스로 점수를 매기고, 내 마지막 제출로 기록한다`
- **준비·실행·확인(Arrange-Act-Assert)** 을 한 테스트에 하나씩. 한 테스트는 한 가지 이유로만 실패한다.
- **데이터는 직접 만든다**: `seedProblem()`, `aProblem({ ... })`, `aCase(...)` — 중요한 값만 드러낸다. 다른 테스트가 만든 데이터에 기대지 않는다.
- **조건을 기다린다, 시간을 기다리지 않는다**: `waitForTimeout` 금지. `await expect(locator).toBeVisible()`, `expect.poll(...)`.
- **사용자처럼 찾는다**: `getByRole`, `getByLabel`, `getByText` 우선. CSS 클래스·DOM 구조에 기대지 않는다(구조가 바뀌어도 동작이 같으면 통과해야 한다).
- **화면 조작은 페이지 객체로**: `e2e/src/pages/*`. 테스트에는 "무엇을"만, 페이지 객체에는 "어떻게"를.
- **요구사항 태그를 단다**: `test.describe('…', { tag: '@R3' }, …)`. 번호는 [요구사항과 테스트 케이스](test-cases.md)에서 고르고, 새 요구사항이면 표에 먼저 추가한다. 태그가 없으면 CI 품질 리포트가 실패한다.
- **기기별 시나리오는 태그로**: `@cross`(Safari 계열도), `@mobile`(아이폰·픽셀), `@tablet`(아이패드). 프로젝트가 태그로 골라 돈다.
- **비밀 값을 테스트에 쓰지 않는다**: 토큰·비밀번호는 `env`에서. 운영 스모크는 읽기만 한다.

## 버그를 고칠 때

0. 결함은 이슈의 **결함 보고** 양식(재현 절차·기대/실제·심각도·증거·발견 위치)으로 남긴다

1. 버그를 재현하는 테스트를 가장 낮은 층에 먼저 쓴다(빨강)
2. 고친다(초록)
3. 정리한다(리팩터링), 테스트는 계속 초록
4. PR 설명에 "어느 층에서 처음 잡혔는지"를 적는다(품질 지표의 결함 발견 위치)

## PR 체크리스트

- [ ] 바뀐 동작에 맞는 테스트가 있다(버그 수정은 재현 테스트)
- [ ] 가장 낮은 층에서 확인했다(UI 테스트는 꼭 필요할 때만)
- [ ] 고정 대기·공유 데이터·순서 의존이 없다
- [ ] 로컬에서 `e2e:ci`를 두 번 연속 통과했다(불안정 확인)
- [ ] 품질 리포트에 새 불안정·새 critical·serious 접근성 위반·품질 게이트 실패가 없다

## 리뷰할 때 보는 것

- 이 테스트가 실패하면 무엇이 깨졌는지 바로 알 수 있는가?
- 구현을 바꿔도(리팩터링) 동작이 같다면 통과하는가?
- 더 낮은 층에서 더 빠르게 확인할 수 있지 않은가?
