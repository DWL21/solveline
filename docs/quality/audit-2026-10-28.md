## 게이트와 운영 경계

`check`, `docker`, `secret-scan`, 단위 커버리지, Sonar, API·UI 검사는 main 필수 체크로 등록되어 있었다. 이번 변경의 불안정 차단은 기존 API·UI 필수 체크에도 적용된다. `품질 리포트` 집계 잡을 필수 체크로 추가하는 저장소 설정 변경은 별도 운영 조치다. PR의 모든 Quality 잡이 통과했는지도 리뷰에서 확인한다.

공개 PR은 GitHub-hosted runner에서만 실행한다. 운영 self-hosted runner·배포·보호 규칙은 변경하지 않는다. 테스트는 별도 Compose 프로젝트와 포트를 사용하며 운영 데이터를 생성하거나 수정하지 않는다.

## 잔여 위험·후속 순서

1. **접근성 serious 위반**: 기준 리포트는 첫 화면·로그인·약관에서 색 대비 위반 30개 노드를 기록했다. critical만 차단하는 현재 정책으로는 이 위반을 막지 못한다. 디자인 변경과 함께 대비 개선 후 serious 기준을 단계적으로 올린다.
2. **OAuth·실기기**: 테스트 전용 로그인은 실제 Google 인증·PKCE·브라우저 쿠키 왕복을 대신하지 않는다. 모바일 프로젝트도 에뮬레이션이므로 실제 iOS·Android 키보드·터치·로그인은 출시 전 수동 확인한다.
3. **보안·공급망**: Sonar의 보안 핫스팟 6건은 자동 취약점 0건과 별개로 사람이 검토해야 한다. 의존성 취약점 검사와 액션 SHA 고정은 별도 기준·갱신 절차를 정해 추가한다.
4. **성능·복구**: 2개 worker의 기능 검증은 부하·지속 실행·백업 복원 훈련을 대체하지 않는다. 큐 적체·runner 장애 복구·실제 백업 복원은 독립 환경에서 검증한다.
5. **배포 시점**: main push의 배포는 Quality와 별도 워크플로여서 동시에 시작한다. 필수 PR 체크를 통한 머지 절차를 지키고, 배포 전 동일 커밋의 모든 검증을 기다리는 정책은 별도 운영 변경으로 검토한다.

실제 실행 명령·결과는 PR의 `검증`에 기록한다. 통과 수는 고정 명세로 쓰지 않고 각 실행 리포트를 기준으로 확인한다.
