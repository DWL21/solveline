# 품질 지표

지표는 "얼마나 많이"가 아니라 "테스트가 일을 하고 있는가"를 보기 위해 고른다. 모든 지표는 `scripts/quality-report.mjs`가 빌드마다 `reports/quality/metrics.json`(추세용)과 `summary.md`(사람용)로 남긴다.

## 1. 지표 정의

| 지표 | 계산 | 목표 | 어디서 |
|---|---|---|---|
| 자동화 통과율 | (통과 + 불안정) / 실행 | 100% | Playwright `results.json` |
| 첫 시도 통과율 | 재시도 없이 통과 / 실행 | ≥ 98% | 같음 |
| 불안정 테스트 수 | 재시도로 통과한 테스트 | 0 (생기면 그 주 안에 해결) | 같음 |
| 실행 시간 | 프로젝트별·전체 소요 시간, 가장 느린 테스트 5개 | PR 파이프라인 10분 이내 | 같음 |
| 커버리지(줄·분기) | 단위 테스트가 지나간 비율(API 코드) | 래칫: 줄 ≥ 80%, 분기 ≥ 66%, 내려가면 실패 | `coverage-summary.json` |
| 품질 게이트 | SonarQube 조건 전부 통과 | OK | `sonar.json` |
| 신뢰성·보안 등급 | 버그·취약점 심각도로 매긴 A~E | A | 같음 |
| 중복 코드 | 중복 줄 비율 | < 5% | 같음 |
| 기술 부채 | 코드 스멜 해결 예상 시간 | 추세 감소 | 같음 |
| 접근성 위반 | axe 위반(심각도별) | critical 0, 나머지 감소 | UI 테스트 첨부 |
| 테스트 층 비율 | 단위 : API : UI : 스모크 | 피라미드 모양 유지 | 리포트 |

## 2. 테스트 효과성 검증

지표가 좋아 보여도 테스트가 결함을 못 잡으면 의미가 없다. 다음으로 효과를 확인한다.

- **결함 발견 위치**: 결함이 어느 층에서 처음 잡혔는지 기록한다(단위·API·UI·정적 분석·운영). 운영에서 처음 발견된 결함은 "새는 결함"으로 보고, 그 결함을 잡을 테스트를 가장 낮은 층에 추가한다.
  - 예) 정적 분석이 찾은 백업 정리 정렬 오류 → 단위 테스트로 재현 후 수정
- **결함 주입 점검(가벼운 뮤테이션)**: 분기마다 핵심 규칙(권한·사용자 분리·채점 비교)을 일부러 깨뜨려 테스트가 실패하는지 본다. 실패하지 않으면 그 규칙의 테스트가 비어 있는 것이다.
- **불안정·느림 추세**: 불안정 테스트와 가장 느린 테스트를 매주 본다. 신뢰가 떨어진 테스트는 결함을 가린다.

## 3. 품질 게이트

| 단계 | 조건 | 실패하면 |
|---|---|---|
| 단위 | 전부 통과 + 커버리지 래칫 | PR 머지 불가 |
| 정적 분석 | 신뢰성 A, 보안 A, 중복 < 5%, 커버리지 ≥ 75%(코드 전체 기준) | PR 머지 불가 |
| API·UI | 전부 통과, 불안정 0, 접근성 critical 0 | PR 머지 불가 |
| 운영 스모크 | 전부 통과 | 알림 → 즉시 확인 |

게이트 기준은 한 번에 올리지 않는다. 지금 수준 바로 아래에서 시작해(래칫) 좋아지면 기준도 같이 올린다.

## 4. 리뷰 주기

- **매 PR**: Step Summary의 품질 리포트(실패·불안정·느린 테스트·정적 분석)
- **매주**: 불안정 테스트 0 확인, 가장 느린 테스트 정리, 접근성 위반 추세
- **매월**: 결함 발견 위치 집계, 래칫 기준 상향 검토, 피라미드 비율 점검


## 집계 자체의 검증

CI는 `node scripts/quality-report.mjs --strict`로 필수 JUnit·커버리지·Playwright·Sonar 결과와 상위 잡 상태를 확인한다. 누락·손상·실패·불안정·전역 오류·필수 프로젝트 실행 누락은 실패로 처리하고, 실패 이유를 `metrics.json`의 `gate.problems`와 Markdown에 남긴다. 집계가 실패해도 아티팩트는 업로드한다.

로컬의 `node scripts/quality-report.mjs`는 부분 집계를 허용하지만 누락을 표시하고 판정을 `incomplete`로 기록한다. 프로젝트 일부의 명시적 skip은 `skipped`로 집계하며, 프로젝트 전체가 skip되면 엄격 게이트가 실패한다. 집계 회귀 테스트는 `pnpm test`에 포함된다.
