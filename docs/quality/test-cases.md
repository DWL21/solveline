# 요구사항과 테스트 케이스

어떤 기능을 어떤 테스트가 지키는지 한 표로 본다. 테스트에는 요구사항 태그(`@R1`…`@R11`)를 달고, 품질 리포트가 요구사항별 통과 수를 집계한다. 태그가 없는 자동화 테스트는 CI에서 실패한다(`scripts/quality-report.mjs --strict`).

```bash
pnpm --filter @solveline/e2e exec playwright test --grep @R3     # 채점 요구사항만
pnpm --filter @solveline/e2e exec playwright test --list --grep @R2   # 권한 테스트 목록
```

## 요구사항

| 번호 | 요구사항 | 위험 | 자동화 수(실행 기준) |
|---|---|---|---|
| R1 | 비회원은 컬렉션과 문제를 읽기 전용으로 둘러볼 수 있다 | 중간 | UI 4 · 스모크 2 |
| R2 | 역할(비회원·사용자·편집 권한·관리자)에 맞는 기능만 쓸 수 있다 | 큼 | API 43 · UI 2 |
| R3 | 제출한 코드를 정확하게 채점한다(판정·점수·시간 제한·히든 케이스) | 매우 큼 | API 16 · UI 5 |
| R4 | 내 코드·메모·폴더·북마크·제출은 다른 사용자에게 보이지 않는다 | 매우 큼 | API 6 |
| R5 | 편집 권한자가 바꾼 공용 문제·컬렉션은 모두에게 적용되고 입력을 검증한다 | 큼 | API 5 · UI 2 |
| R6 | 관리자 모드는 마스터 비밀번호로만 들어가고 편집 권한을 줄 수 있다 | 큼 | UI 2 |
| R7 | 작성한 코드는 자동 저장되어 새로고침해도 남는다 | 큼 | UI 1 |
| R8 | 휴대폰·태블릿에서도 문제를 읽고 풀 수 있다 | 중간 | UI 5 |
| R9 | 주요 화면에 치명적인 접근성 위반이 없다 | 중간 | UI 3 |
| R10 | API는 공유 계약·오류 형식·보안 헤더를 지킨다 | 큼 | API 3 |
| R11 | 운영 사이트의 핵심 경로가 살아 있다 | 큼 | 스모크 4 |

수는 실행 단위(기기 프로젝트별 실행 포함)로 센다. 테스트 하나가 두 요구사항을 지키면 양쪽에 센다. 실행할 때마다 실제 수는 품질 리포트의 "요구사항별" 표를 기준으로 한다.

## 실행하는 기기

| 프로젝트 | 무엇을 | 고르는 방법 |
|---|---|---|
| api | API 테스트 전부 | `tests/api` |
| desktop-chromium | UI 테스트 전부(휴대폰·태블릿 전용 제외) | 태그 `@mobile`·`@tablet` 제외 |
| desktop-webkit | Safari 계열 핵심 경로 | 태그 `@cross` |
| mobile-iphone · mobile-pixel | 휴대폰 배치 | 태그 `@mobile` |
| tablet-ipad | 태블릿 배치 | 태그 `@tablet` |
| smoke | 운영 읽기 전용 | `tests/smoke`, 매일 09:00 |

## 시연(통과한 테스트도 증거 남기기)

GitHub Actions → CI → Run workflow에서 `demo`를 켜면 모든 테스트의 영상·trace·스크린샷이 `e2e` 아티팩트(`reports/html`)에 남는다. 평소 실행은 실패한 테스트만 남겨 아티팩트를 작게 유지한다.
